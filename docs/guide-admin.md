# 管理者ガイド

リポジトリに mdait を導入し、翻訳運用を設計・維持する人のためのガイド。日々の翻訳操作は [利用者ガイド](guide-user.md) を参照。

## セットアップ

1. [リリースページ](https://github.com/mochimochiki/mdait/releases) から `mdait-<version>.vsix` を取得し、`Ctrl+Shift+P` → **Extensions: Install from VSIX...** でインストールする
2. アクティビティバーの 🌐 アイコンで mdait ビューを開き、**設定ファイルを作成** を押す（`.mdait/mdait.json` が生成される）
3. `transPairs` と `primaryLang` を自分のリポジトリに合わせる（後述）
4. **初回同期** を押す。原文が走査され、訳文ファイルとマーカーが用意される
5. ビュー上部の **✨翻訳** で訳文を生成する

すでに訳文が揃っているリポジトリでは、手順 4 の代わりに [既存翻訳の取り込み](#既存翻訳の取り込み) を使う。

設定は `.mdait/mdait.json` を直接編集するほか、ビュー上部の **設定画面を開く** から VS Code の設定画面に似た GUI で編集できる。

## 設定早見表

`.mdait/mdait.json` の全項目。

| キー | 既定値 | 意味 |
|---|---|---|
| `transPairs` | 必須 | 翻訳ペア（原文／訳文のディレクトリと言語） |
| `primaryLang` | 必須 | 用語集・翻訳メモリの基準言語。通常は原文の言語 |
| `ignoredPatterns` | `"**/node_modules/**"` | 処理から除外する glob。文字列または配列 |
| `markers.mode` | `"embedded"` | マーカーの保管先（`embedded` / `external`） |
| `sync.level` | `3` | ユニットの区切りとする見出しの深さ（`3` なら h1〜h3） |
| `sync.autoSyncOnSave` | `true` | 保存時に自動同期する |
| `sync.orphanTargetPolicy` | `"delete"` | 原文が消えたユニットの扱い（`delete` / `verify`） |
| `sync.copyAssets` | `true` | 差分ユニット内の画像などを訳文側へコピー。`false` または拡張子の配列も可 |
| `ai.provider` / `ai.model` | — | AI プロバイダーとモデル |
| `trans.contextSize` | `1` | 翻訳時に前後何ユニットを文脈として渡すか |
| `trans.retryLimit` | `1` | 翻訳失敗時のリトライ上限（1〜5） |
| `trans.concurrency` | `3` | ディレクトリ翻訳のファイル単位並列数（1〜8） |
| `trans.maxUnitsPerRun` | `300` | 1 回の実行で扱うユニット数の上限。`0` で無制限 |
| `trans.frontmatter.keys` | `["title", "description"]` | 翻訳する FrontMatter のキー。`[]` で翻訳しない |
| `trans.extensions` | `[]` | Markdown 以外に翻訳する拡張子（例 `[".txt"]`） |
| `trans.maxFileSize` | `51200` | Markdown 以外のファイルのサイズ上限（バイト） |
| `terms.filename` | `"terms.csv"` | 用語集ファイル名（`.csv` / `.yaml`） |
| `tm.enabled` | `true` | 翻訳メモリの有効・無効 |
| `tm.maxReferences` | `5` | 1 回の翻訳プロンプトに載せる参照訳の上限 |
| `tm.minQueryLength` | `10` | 翻訳メモリを検索する最小文字数 |
| `tm.retryLimit` | `1` | TM 登録のリトライ上限 |
| `aiReview.autoApprove` | `true` | AI が高確信で一致と判定したユニットの `need:review` を自動で外す |
| `aiReview.batchSize` | `3` | AI 翻訳レビュー 1 回あたりの検証ペア数 |

`sync.level` だけはファイル単位で上書きできる。

```yaml
---
mdait:
  sync:
    level: 2
---
```

## 翻訳ペア

パスは `.mdait/` の親ディレクトリ（通常はリポジトリルート）からの相対で書く。1 つの原文から複数言語へ展開する場合はペアを並べる。

```json
{
  "transPairs": [
    { "sourceLang": "ja", "sourceDir": "docs/ja", "targetLang": "en", "targetDir": "docs/en" },
    { "sourceLang": "ja", "sourceDir": "docs/ja", "targetLang": "de", "targetDir": "docs/de" }
  ],
  "primaryLang": "ja"
}
```

`primaryLang` を省略すると同期が「Primary language (primaryLang) is not configured.」で止まる。

ペアごとに `copyAssets` を書けば、画像コピーの挙動を言語別に変えられる（例: 英語版だけ画像を差し替えるので `false`）。

原文と訳文のディレクトリは、同一にも入れ子にもしないこと。再帰的な処理の原因になる（**mdait: セットアップ診断** が検出する）。

## AI プロバイダー

| プロバイダー | `provider` | 備考 |
|---|---|---|
| VS Code Language Model API | `vscode-lm` | 推奨。GitHub Copilot 経由で追加設定が不要 |
| OpenAI | `openai` | API キーが必要。互換エンドポイントも指定可 |
| Ollama | `ollama` | ローカルサーバー。`endpoint` と `model` を指定 |

```json
{
  "ai": {
    "provider": "openai",
    "model": "gpt-4o",
    "openai": { "apiKey": "${env:OPENAI_API_KEY}", "baseURL": "https://api.openai.com/v1" }
  }
}
```

`.mdait/.gitignore` が無視するのは `local/`（ログ・実行レポート・手元の控え）だけで、`mdait.json` は Git の追跡対象になる。API キーは必ず `${env:...}` で環境変数から読む。直書きしてコミットしてしまった場合は、履歴を消すだけでは足りないので鍵そのものを無効化する。

## 既存翻訳の取り込み

手翻訳や別ツールで作った訳文がすでにあるリポジトリでは、そのまま同期すると既訳に `need:translate` が付き、次の翻訳で **AI に上書きされる**。これを防ぐのが取り込み（adopt）である。

ビュー上部の **✨既存翻訳の取り込み** を押すと、次の 4 段が 1 操作で走る。実行前に Git へコミットしておくこと（マーカー・用語集・翻訳メモリに書き込むため）。

1. **取り込み** — マーカーのない既訳に `from` を張り、`need:review` を付ける。本文は 1 文字も変わらない。章の欠落や順序の入れ替えによる位置ずれは AI が補正する
2. **AI 翻訳レビュー** — 取り込んだ全ペアを判定する。忠実で完全と判定されたユニットは `need:review` が自動で外れ、誤ったペアと訳抜けの疑いだけが残る
3. **用語集の構築**（既定オン）— 確立した対訳ペアから用語を検出し、訳語を補う
4. **翻訳メモリの構築**（既定オン）— レビューを通ったペアを登録する。`need:review` が残るペアは登録されないため、翻訳メモリは汚れない

完了後、レポートが `.mdait/local/reports/adopt.md` に書き出される。完了通知の「レポートを開く」ボタンでプレビュー表示できる。表の各ユニットは該当箇所へのリンクになっているので、エスカレーションされたユニットだけを踏んで確認すれば取り込みは終わる。レポートは実行のたびに上書きされる。レビューを片付けてから TM 登録を実行すれば、残りのペアも翻訳メモリに入る。

取り込みは**移行時に一度だけ行う操作**で、定常運用の同期では使わない。

### 訳文側だけにあるセクション

英語版限定の案内など、原文に対応相手のないセクションは、同期が `need:review` を付けて保護する（削除も翻訳もしない）。文書の意図を知る人が次の 3 つから選ぶ。

| 判断 | 操作 | 結果 |
|---|---|---|
| 独自の章として残す | `need:review` を外し `<!-- mdait {hash} -->` だけにする | 独立ユニットとして恒久保持。翻訳・削除・翻訳率の対象外 |
| その言語限定にする | `need:isolate` に書き換える（対訳ペアがあるユニットは CodeLens の「その他」→「凍結する」） | 保持に加え、そのファイルをさらに別言語へ展開するときも伝播しない |
| 不要 | ユニットごと削除する | 訳文から消える |

原文側にしかない補足章を訳させたくない場合は、その原文ユニットの CodeLens で「その他」→「凍結する」を選ぶ（`need:isolate` が付く）。以降そのユニットは凍結され、原文を直しても訳文へ改訂が流れなくなる点に注意する。

### ペアがずれていたとき

対応付けは見出しの順序に基づくため、章の増減が大きいファイルでは誤ったペアが生じうる。`need:review` が残っている限り翻訳にも翻訳メモリにも流出しないので既訳は壊れないが、`from` リンクは次回以降の同期が維持するため自然には直らない。復旧は次の順で行う。

1. 誤ったペアと判定された訳文側ユニットのマーカー行を削除してリンクを外す
2. 章の順序が原文とずれていれば、訳文側を原文の順に並べ替える（欠落章は放置してよい。再同期が正しい位置に空ユニットを作る）
3. もう一度取り込みを実行する。正しく対応済みのユニットがアンカーとして働き、外したユニットだけがその区間内で対応付け直される

網羅的なパターン一覧は [command_adopt.md](design/command_adopt.md) にある。

## 用語集

`.mdait/terms.csv` に登録した用語は、翻訳のたびにプロンプトへ自動で注入される。単語レベルの表記ゆれ（unit を「ユニット」「単位」「ブロック」と訳し分けてしまう類）を抑えるための仕組み。

```csv
term,en,variants_en,ja,context
unit,unit,,ユニット,Markdown見出し単位のブロック
TM,TM,,TM,翻訳メモリ。「翻訳メモリ」と訳さずTMのまま使う
```

`term` はキーなので後から変えない。`context` には「〜と訳さないこと」のような禁止ルールも書ける。`variants_<言語>` は表記ゆれ（大文字小文字差・ハイフンの有無・誤記など）で、用語の照合に使われる。

育て方は 2 段。原文側の行の **✨用語検出** で候補を抽出し（既存の行は上書きされない）、翻訳が済んだ行の **✨用語をこの言語へ展開** で空欄の訳語を既訳から推定させる。どちらも AI の下書きなので、最終的には人が確認する。

登録するのは実際に揺れている用語だけでよい。網羅するとプロンプトが膨らむだけで効果は上がらない。`terms.filename` を `terms.yaml` にすれば YAML でも書ける（項目の意味は同じ。混在は不可）。

## 翻訳メモリ

用語集が単語の一貫性を担うのに対し、翻訳メモリは**文・フレーズの一貫性**を担う。実体は `.mdait/translations.tmx`（業界標準の TMX 形式）。

翻訳が済んで内容を承認したら、行の **✨TM登録** を実行する。対象は `from` があり `need` がないユニット、つまり完成しているものだけ。登録時は AI が対訳の品質を検証し、明らかな誤訳は弾く。同じペアを何度登録しても重複しない。

以降の翻訳では、類似する原文が自動で検索され、参照訳としてプロンプトに載る。蓄積が増えるほど文体と用語が安定する。

翻訳しただけでは登録されない。**✨TM登録** を実行して初めて蓄積される。リセットしたいときは `translations.tmx` を削除すればよい。

## マーカーの保管方式

既定（`markers.mode: "embedded"`）では、状態は Markdown 本文の HTML コメントとして保持される。文書だけで完結し、`git diff` に自然に現れる。

`"external"` にすると、マーカーは本文から出て `.mdait/unit-state`（TSV 1 ファイル）に集約される。本文を汚したくない場合や、HTML コメントを書けない `.txt` / `.csv` を翻訳対象に含める場合に選ぶ。集約ファイルなので並行翻訳が競合しうるが、ファイルごとのブロック・行ごとの目印・ファイルIDで自分を名乗る行という形で競合を避けており、次の同期で正規化されるため、独立した編集は自動でマージされる。**git の `merge=union` には頼らない** — SVN に無く、効いた先で黙って片方を捨てていたので、`.mdait/.gitattributes` は書き出さず、既にある作業場からはその指定を外す（ADR-260911-01）。それでも残った競合は、mdait のビューの「競合の解決」に出る。

なお、**git を使うなら `merge.conflictStyle` を `diff3` か `zdiff3` にしておくこと**。マージしたときに「両者が何から分かれたか」が記録されるので、「片方だけが直した」形を mdait が決定的に片付けられる。設定していないと、その形も人の判断に回る（実測: 500語の用語集に両側10語ずつ足す形で、判断が要る件が 45件 → 0件になった）。

```bash
git config merge.conflictStyle zdiff3
```

既存文書は **mdait: マーカーを外部化** / **mdait: マーカーを本文へ埋め込み** で相互に変換できる。外部化では、**外部モードのユニット境界に乗っていないマーカーが失われる** — `sync.level` より深い見出しに付いたもの（既定 `level: 3` なら `####` 以下）と、見出しを伴わない手動のサブユニット境界マーカーである。落ちたマーカーは `from`（どの原文から訳したか）と `need` も一緒に失う。落とした件数は変換の完了通知に出る。

## Git 運用

`.mdait/` はまるごとコミットする。`mdait.json`（設定）・`terms.csv`（用語集）・`translations.tmx`（翻訳メモリ）・`unit-state`（外部モード時）はいずれもチームで共有する資産である。

`.mdait/local/`（実行レポート・ログ・手元の控え）は追跡から外れる。レポートは「その人がいつ何を実行したか」の記録で、チームで共有する資産ではない。ファイル名が種類ごとに固定で実行のたびに全文が書き換わるため、共有すると2人が同じコマンドを走らせるだけで競合する。

翻訳状態は文書とサイドカーの中にしかないので、外部 DB もマイグレーションも要らない。取り込みや一括翻訳のような大きな書き込みの前にコミットしておけば、いつでも `git checkout` で戻せる。

複数人が同時に TM 登録して `translations.tmx` が競合したら、mdait のビューの「競合の解決」で片付ける。原文ごとに突き合わせるので、片方にしか無い登録はそのまま両方残る。人が選ぶのは、同じ原文に別々の訳が登録された件だけである。

## SVN 運用

`.mdait/`（`local/` を除く）をまるごとコミットするのは Git と同じである。違いは3つある。日本語の多い原稿を SVN がバイナリと判定すること、競合を SVN の側でも「解決済み」にする必要があること、VS Code の外で原稿を改名すると訳文が付いていかないことである。コマンドは svn 1.14（TortoiseSVN 同梱のコマンドライン）と PowerShell 7 で確かめた。メニューの名前は TortoiseSVN のもの。

### 最初に1回だけ（管理者）

TortoiseSVN を入れるときに「command line client tools」に印を付けておく（既定では入らない）。入っていないと、下の `svn` が「認識されません」で止まる。

作業コピーの根（trunk）で、PowerShell から次のまとまりをそのまま貼り付けて実行する。何度実行しても結果は同じになる。

```powershell
$files = svn list -R | Select-String '\.(md|txt|csv|json|tmx)$|^\.mdait/unit-state$' | ForEach-Object Line
[IO.File]::WriteAllLines("$PWD\mdait-targets.txt", [string[]]$files)
svn propset svn:mime-type text/plain --targets mdait-targets.txt
Remove-Item mdait-targets.txt
$props = @(svn propget svn:auto-props . 2>$null | Where-Object { $_ -ne '' })
foreach ($p in '*.md', '*.txt', '*.csv', '*.json', '*.tmx', 'unit-state') {
  $i = @($props | ForEach-Object { ($_ -split '=', 2)[0].Trim() }).IndexOf($p)
  if ($i -lt 0) { $props += "$p = svn:mime-type=text/plain" } elseif ($props[$i] -notmatch 'svn:mime-type') { $props[$i] += ';svn:mime-type=text/plain' }
}
svn propset svn:auto-props ($props -join "`n") .
$ignore = @(svn propget svn:ignore .mdait 2>$null | Where-Object { $_ -ne '' -and $_ -ne 'local' }) + 'local'
svn propset svn:ignore ($ignore -join "`n") .mdait
svn commit -m "mdait: SVN の設定"
```

1. 1〜4行目は、いまある原稿と `.mdait` の中のファイルをテキストとして登録し直す。SVN は日本語の多いファイルをバイナリと判定する（実測: 原文25本のうち12本）。バイナリのままだと、2人が別々の章を直しただけで必ず競合し、差分も見られない。ファイルの一覧をいったん書き出すのは、数百本でもコマンドの長さの上限に当たらないようにするため。
2. 5〜10行目は、これから足すファイルにも同じ設定を効かせる（`svn:auto-props`）。すでにある設定は残し、mdait の分だけを書き足す。
3. 11〜12行目は、`.mdait/local/` をコミットの対象から外す（`svn:ignore`）。ここも、すでにある設定は残す。

`.mdait/` と訳文には `svn:needs-lock` を掛けない。読み取り専用のファイルには、同期も翻訳も書き込めない。

### 毎日の作業（mdait を使う人）

1. 作業の前に「SVN 更新」をする。
2. 競合が出たら、同期の前に次の順で解く。
   1. `.mdait` の外のファイル（原稿）は「競合の編集」で直し、「解決済み」にする。
   2. VS Code の mdait ビューで「競合を解決」を押す。
   3. `.mdait` の中の競合したファイルを「解決済み」にする。コマンドは、mdait の完了通知に出たものをそのまま実行する（対象のパスが入っている）。`--accept` を付けるときは、対象のパスと `-R` を省かない。省くと何も解決されない。
3. 同期する。そのあと、翻訳などいつもの作業をする。
4. コミットの直前にもう一度「SVN 更新」をする。競合が出たら 2 に戻る。
5. 「SVN コミット」をする。コミット画面で「バージョン管理外のファイルを表示」に印を付け、訳文のフォルダに増えたファイルも選ぶ。

競合を残したまま同期しない。競合マーカーが残る原稿と、SVN が横に `.mine` や `.r<N>` を置いた原稿は、同期が見送って通知で伝える。改名や削除が絡む競合（ツリー競合）は見分けられず、移動前の名前で原文を丸写しした訳文が作られる。ツリー競合は、作業コピーの根で `svn resolve <競合したパス>` を実行する（`--accept` は付けない）。手元で直した原稿を相手が改名した形では、svn は何も聞かずに変更を改名先へ移して解決した（svn 1.14 で確認）。

### mdait を使わない人との約束

原稿を改名・移動するときは、原文と訳文を一緒に、同じ名前へ動かす。VS Code の外で原文だけを動かすと、訳文は付いていかない。

片方だけ動いていることに気づいたら、同期の前に訳文も同じ名前へ動かす。状態はそのまま引き継がれる。先に同期してしまった場合は、同期が作った訳文（原文の丸写し）を消してから訳文を動かし、もう一度同期する。訳はすべて残るが、その原稿の章はすべて確認待ちになる。

翻訳待ちの章を手で訳してかまわない。次の同期で確認待ちに変わり、AI の翻訳で上書きされない。

## プロンプトにドメイン知識を足す

`.mdait/mdait-instructions.md` を置くと、その内容が AI へのプロンプトに追加される。

```markdown
---
prompts: ["trans.translate"]
---

# ドメイン知識
この製品では「ユニット」は Markdown 見出し単位のブロックを指す。
「TM」は「翻訳メモリ」と訳さず、そのまま「TM」を使う。
```

`prompts` で適用先を絞れる（省略時は全プロンプト）。文体の指定や禁止表現の列挙にも使える。プロンプト ID の一覧は [prompt.md](design/prompt.md) を参照。

## トラブルシューティング

まず **mdait: セットアップ診断** を実行する。設定の不備・ディレクトリの誤り・AI への到達性・API キーの直書きをまとめて点検する。

**「Primary language (primaryLang) is not configured.」**
`primaryLang` がない。原文の言語コードを追加する。設定ファイルを手書きでコピーしたときに落ちやすい。

**「Language model is not available」**
既定の `vscode-lm` は GitHub Copilot 経由で動く。Copilot の導入とサインインを確認する。特定モデルが使えない場合、mdait は `gpt-4o` から利用可能なモデルへ自動でフォールバックするが、`ai.model` を実在するモデル名に合わせる方が確実。Copilot を使わない構成では `openai` か `ollama` に切り替える。

**原文の章を消したら訳文も消えた**
`sync.orphanTargetPolicy` の既定 `"delete"` が、原文に対応相手のない管理済みユニットを自動削除する。判断を毎回人に委ねるなら `"verify"` にする（`need:verify-deletion` が付いて残る）。マーカーのない訳文と独立ユニットはこのポリシーの対象外で、常に保持される。

**一括翻訳がレート制限で失敗する**
`trans.concurrency` を下げる（`1` で逐次実行）。1 回の実行が大きすぎる場合は `trans.maxUnitsPerRun` で頭を抑える。

**ユニットの区切りを変えたら差分が大量に出た**
`sync.level` を変えると既存マーカーと境界が食い違う。変更後は全ファイルを同期し直す。
