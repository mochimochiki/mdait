# TM — 翻訳メモリで訳文品質を積み上げる

過去の翻訳実績をファイルに蓄積し、次回の翻訳プロンプトへ自動注入することで、用語・文体の一貫性を高めるしくみです。

---

<!-- mdait 2fd1f4ce -->
## なぜ翻訳メモリが必要か

AI はリクエストごとに独立して動作します。  
同じ文でも実行タイミングによって訳し方が微妙に変わることがあります。

**TM なし:**  
「This extension supports Markdown files.」  
→ 「この拡張機能は Markdown ファイルをサポートします。」  
→ 「本拡張は Markdown ファイルに対応しています。」（別回の翻訳）

**TM あり:**  
過去の訳文が参照として渡されるため、文体・用語が安定します。

用語集（`terms.csv`）が「単語レベル」の一貫性を担うのに対し、  
翻訳メモリは**文・フレーズレベル**の一貫性を担います。

---

<!-- mdait 7dc78874 -->
## TMX ファイルの場所

翻訳メモリの実体は `.mdait/translations.tmx` です。

- TMX（Translation Memory Exchange）は業界標準の XML 形式
- プロジェクトルート配下に自動生成される
- Git にコミットすることでチーム間での共有が可能

```
your-project/
└── .mdait/
    ├── translations.tmx   ← 翻訳メモリ本体
    └── terms.csv
```

<!-- mdait e5051fab -->
## tm-commit — 翻訳実績を TM に登録する

翻訳済みユニットから対訳ペアを抽出し、TMX ファイルへ登録するコマンドです。

<!-- mdait 6bb3503f -->
### いつ実行するか

`trans` で翻訳が完了したあと、内容を確認・承認したタイミングで実行します。

```
trans（翻訳） → レビュー → tm-commit（TM 登録） → 次回 trans でこの訳文が参照される
```

<!-- mdait 223bc3e1 -->
### 実行手順

1. StatusTree を開く（アクティビティバーの mdait アイコン）
2. 登録したいファイルまたはディレクトリの行右端にある **TM 登録ボタン**（🗄 アイコン）をクリック

ディレクトリを選択すると、配下の全翻訳済みファイルをまとめて登録できます。

<!-- mdait 9413add9 -->
### 処理対象

`from` あり かつ `need` なし のユニットのみが対象です。  
つまり**翻訳が完了している**ユニットだけが TM に登録されます。

| 状態 | tm-commit の対象 |
|---|---|
| `need:translate`（未翻訳） | ✗ スキップ |
| `need:revise`（要改訂） | ✗ スキップ |
| `need:review`（要確認） | ✗ スキップ |
| `need` なし（翻訳済み） | ✓ 登録対象 |

---

<!-- mdait de60d47c -->
## LLM-guard による品質検証

tm-commit 時、LLM が対訳ペアの品質を自動検証します。

- 明らかな誤訳・無関係なペアは登録を拒否
- 検証済みペアのみ upsert（再実行しても重複しない）

手動で品質チェックしなくても、低品質なペアが混入しにくい構造になっています。

<!-- mdait fa4c0083 -->
## 翻訳時の参照自動注入

`trans` を実行すると、TM 内の類似文を自動で検索し、プロンプトへ参照として挿入します。

```
# 翻訳メモリ参照
- 原文: "This extension helps translate Markdown files."
  訳文: "この拡張機能はMarkdownファイルの翻訳を支援します。"
- 原文: "Run the sync command before translating."
  訳文: "翻訳前に sync コマンドを実行してください。"
```

TM に蓄積が増えるほど、翻訳精度・一貫性が向上します。  
ゼロから始めて、`tm-commit` を繰り返すことで効果が積み上がります。

## 設定オプション

`mdait.json` の `tm` セクションで制御します。

| フィールド | デフォルト | 説明 |
|---|---|---|
| `tm.enabled` | `true` | `false` で TM 機能を完全無効化 |
| `tm.maxReferences` | `5` | プロンプトに含める参照の最大数 |
| `tm.retryLimit` | `1` | tm-commit のリトライ上限 |
| `tm.minQueryLength` | `10` | TM 検索の最小クエリ長（文字数）|

<!-- mdait 20bccc77 -->
### tm.enabled

`false` にすると `trans` 時の参照注入・`tm-commit` の両方が無効になります。  
TM の効果を試したくない場合や、プロンプトを軽くしたい場合に使います。

```json
{
  "tm": {
    "enabled": false
  }
}
```

<!-- mdait 57b8c209 -->
### tm.maxReferences

プロンプトに注入する参照の上限数です。  
多いほど一貫性は上がりますが、プロンプトが長くなり LLM コストも増加します。  
通常は `5`（デフォルト）で十分です。文書量が多い場合は `3` に下げることも選択肢です。

<!-- mdait 9887ebc1 -->
### tm.minQueryLength

TM 検索クエリが短すぎる場合に検索をスキップします。  
短すぎる文は類似文を正確に絞れないため、ノイズ参照を防ぐ設定です。

## よくあるユースケースと注意点

<!-- mdait e14000fe -->
### 初回セットアップ

1. 既存の翻訳済みファイルがある場合、StatusTree のルートディレクトリ行の **TM 登録ボタン**（🗄 アイコン）をクリックしてまとめて蓄積できます。
2. `.mdait/translations.tmx` が Git リポジトリに含まれていることを確認してください。

<!-- mdait e966c7e6 -->
### チームで共有する

`.mdait/translations.tmx` を Git にコミットすることで、チームメンバー全員が同じ TM を利用できます。  
CI でのマージ競合に注意してください（同じファイルを複数人が同時に `tm-commit` すると競合が起きます）。

<!-- mdait a5549e50 -->
### TM をリセットしたい

`.mdait/translations.tmx` を削除または空にすることでリセットできます。  
次回 `tm-commit` から再蓄積が始まります。

<!-- mdait 5f8ac165 -->
### 注意点

- `trans` を実行しただけでは TM は更新されません。`tm-commit` が必要です。
- TM は参照として使われるだけで、訳文を上書きするものではありません。
- `minQueryLength` 未満の短い文は TM 参照の対象外です。
