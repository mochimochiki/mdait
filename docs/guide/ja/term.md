# Term — ドメイン用語を登録して翻訳の一貫性を高める

AI翻訳で同じ概念が毎回違う訳語になる問題を、用語集（`terms.csv`）で解決するページです。

---

<!-- mdait 299ed0ed -->
## 用語管理が必要な理由

AI はリクエストごとに独立して動作するため、同じ英単語でも文脈によって訳し方が変わることがあります。

**ない場合:**
- 「unit」→ 「ユニット」「単位」「ブロック」が混在
- 「sync」→ 「同期」「シンク」「更新」が混在

**ある場合:**
- 全ユニットで「unit → ユニット」が統一される
- 翻訳プロンプトに用語集が自動で注入される

用語集はプロジェクトルートの `.mdait/terms.csv` に保存します。`trans` 実行時に自動参照されます。

---

<!-- mdait ae7ef34c -->
## term.detect — 用語候補を自動抽出する

ソースファイルを AI に解析させ、専門用語・固有名詞・製品名などを `terms.csv` に追加します。既存エントリは上書きされず、不足分のみマージされます。

**起動方法:**

| 方法 | 操作 |
|---|---|
| StatusTree（ディレクトリ行） | ソースディレクトリ行の「Detect Terms」ボタン |
| StatusTree（ファイル行） | ソースファイル行の「Detect Terms」ボタン |

**detect 前（`terms.csv` が空の状態）:**

```csv
term,en,ja,context
```

**detect 後（ソース「mdait は Markdown 翻訳ツールです」を解析）:**

```csv
term,en,ja,context
mdait,mdait,mdait,VS Code拡張機能の製品名
Markdown,Markdown,Markdown,マークアップ言語
```

AI が抽出した用語が追加されます。`ja` や `context` が空の場合は次の `term.expand` で補完します。

---

<!-- mdait b0734a65 -->
## term.expand — 訳語の空欄を自動補完する

`terms.csv` の中で `en` または `ja` が空の行を対象に、既存の翻訳済みユニットを参照して AI が訳語を推定・補完します。

**起動方法:**

| 方法 | 操作 |
|---|---|
| StatusTree（ディレクトリ行） | 翻訳完了ディレクトリ行の「Expand Terms」ボタン |
| StatusTree（ファイル行） | 翻訳完了ファイル行の「Expand Terms」ボタン |

**expand 前（`en` と `ja` の一部が空）:**

```csv
term,en,ja,context
unit,,ユニット,
marker,marker,,状態管理用HTMLコメント
sync,,,
```

**expand 後（AI が既存訳文から推定して補完）:**

```csv
term,en,ja,context
unit,unit,ユニット,Markdown見出し単位のブロック
marker,marker,マーカー,状態管理用HTMLコメント
sync,sync,同期,マーカーの挿入・更新操作
```

補完された値は確定ではありません。内容を確認し、必要に応じて手動で修正してください。

## CSV フォーマット

デフォルトのファイルは `.mdait/terms.csv` です。

| カラム | 必須 | 説明 |
|---|---|---|
| `term` | ◎ | 用語の識別キー。通常はソース言語の単語 |
| `en` | △ | 英語での表記 |
| `ja` | △ | 日本語訳。翻訳プロンプトに注入される |
| `context` | 任意 | 用語の意味・使用場面の補足説明 |

`en` と `ja` は最低どちらか一方があれば機能します。`context` があると AI の訳語精度が上がります。

**記述例:**

```csv
term,en,ja,context
unit,unit,ユニット,Markdown見出し単位のブロック
marker,marker,マーカー,状態管理用HTMLコメント
sync,sync,同期,マーカーの挿入・更新操作
TM,TM,TM,翻訳メモリ。略語をそのまま維持すること
```

## YAML 形式を使う

CSV の代わりに YAML を使うこともできます。リスト形式で管理しやすい場合に向いています。

**`terms.yaml` の例:**

```yaml
- term: unit
  en: unit
  ja: ユニット
  context: Markdown見出し単位のブロック
- term: marker
  en: marker
  ja: マーカー
  context: 状態管理用HTMLコメント
```

**`mdait.json` で切り替え:**

```json
{
  "terms": {
    "filename": "terms.yaml"
  }
}
```

CSV と YAML でカラム・フィールドの意味は同一です。混在はできません。どちらか一方で統一してください。

<!-- mdait b2db2399 -->
## 手動編集のポイント

用語集は手動で直接編集するのが基本です。AI の提案を下書きとして使い、最終的には人間が確認します。

- **`term` は変えない** — キーとして参照されるため、途中で変更すると既存エントリとの照合がずれます
- **訳語を「使ってほしくない表現」にしない** — AI は `ja` の値をそのまま使う傾向があります
- **`context` で禁止ルールも書ける** — 例: `context: 「TM」のまま使用。「翻訳メモリ」と訳さないこと`
- **空行はスキップされる** — CSV で空行があっても無視されます

## 翻訳への自動注入

`trans` 実行時、mdait は `terms.csv`（または `terms.yaml`）を読み込み、翻訳プロンプトに用語集を付加します。

```
[翻訳プロンプト]
以下の用語集に従って訳してください：
- unit → ユニット（Markdown見出し単位のブロック）
- marker → マーカー（状態管理用HTMLコメント）
- sync → 同期（マーカーの挿入・更新操作）
```

注入は自動で行われます。`trans` コマンドに追加設定は不要です。用語集が空の場合は注入されません。

## 設定オプション

`.mdait/mdait.json` の `terms` セクションで設定します。

| フィールド | デフォルト | 説明 |
|---|---|---|
| `terms.filename` | `terms.csv` | 用語集ファイル名。`.mdait/` 配下に配置 |

現状の設定項目は `filename` のみです。ファイル形式は拡張子（`.csv` / `.yaml`）で自動判別します。

```json
{
  "terms": {
    "filename": "terms.yaml"
  }
}
```

## よくあるユースケースと注意点

**同じ英単語に複数の訳語が混在している**
→ `term.detect` を実行後、`ja` カラムを統一した訳語で手動修正します。以降の翻訳はその訳語で固定されます。

**用語が多すぎてプロンプトが長くなる**
→ 実際に翻訳で揺れが出ている用語に絞って登録します。全用語を網羅する必要はありません。

**`term.expand` が意図しない訳語を補完した**
→ 補完は AI の推定です。必ず確認し、`ja` カラムを直接書き直してください。

**新しいファイルを追加するたびに `term.detect` が必要か**
→ 必須ではありません。用語が安定したら detect を止め、手動メンテに移行して問題ありません。

**チームで用語集を共有したい**
→ `terms.csv` を Git で管理します。`.mdait/` ごとコミットしてください。
