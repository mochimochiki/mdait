# トラブルシューティング — よくある落とし穴と対処

mdait を使い始めた直後に嵌まりやすい点を「症状 → 原因 → 対処」でまとめています。多くは **`mdait: セットアップ診断（Diagnose Setup）`** コマンドで一括点検できます。コマンドパレット（`Ctrl+Shift+P`）から実行するか、mdait ビューの Welcome 画面のボタンを使ってください。

---

## Sync したのに訳文が空っぽ（「壊れた？」）

**症状:** Sync 後、ターゲットディレクトリにファイルはできたが中身が空（マーカーだけ）。

**原因:** これは**正常な動作**です。Sync は原文をコピーせず、翻訳枠（マーカー）だけを用意します。実際の訳文は次の **Trans（翻訳）** で書き込まれます。

**対処:** StatusTree でファイル/ディレクトリの ▶ ボタン、または原文の各マーカー上の「翻訳」CodeLens を実行してください。Sync 完了通知の「今すぐ翻訳」からも実行できます。

---

## Sync で「Primary language (primaryLang) is not configured.」と出る

**症状:** Sync 実行時に上記エラー。

**原因:** `.mdait/mdait.json` に **`primaryLang`** がありません。ドキュメントの一部の例では省略されているため、手書きでコピーすると欠落しがちです。

**対処:** `primaryLang` を追加します（通常は原文の言語コード）。

```json
{
  "transPairs": [ /* ... */ ],
  "primaryLang": "ja"
}
```

「Create mdait.json」ボタンで生成したテンプレートには既定値が入っています。`mdait: セットアップ診断` でも検出されます。

---

## 翻訳しようとすると「No translation pair found」「does not need translation」

**症状:** 翻訳コマンドがエラーになる、または「翻訳不要」と言われる。

**原因と対処:**

- **原文ファイルを翻訳しようとしている** — 翻訳できるのは**ターゲット側**のファイルです。原文（sourceDir）ではなく、訳文（targetDir）側で実行してください。
- **まだ Sync していない** — 先に **Sync** を実行してマーカーを付与してください。
- **`need` フラグが無い** — そのユニットは既に最新です。原文を変更すると `need:revise` が付きます。

迷ったら StatusTree の ▶ ボタンを使うのが安全です（常にターゲット側を対象にします）。

---

## AI 翻訳が動かない（「Language model is not available...」）

**症状:** 翻訳実行時に「追加設定不要」のはずの `vscode-lm` でエラー。

**原因:** `vscode-lm`（既定）は **GitHub Copilot** 経由で動きます。Copilot 拡張機能の導入と有効なサブスクリプションが前提です。

**対処:**

- GitHub Copilot を導入・サインインし、有効化する。
- それでも特定モデルが使えない場合、mdait は `gpt-4o` → 利用可能な任意モデルへ自動フォールバックします。`ai.model` を実際に使えるモデル名に合わせると確実です。
- Copilot を使わない場合は `ai.provider` を `openai` か `ollama` に切り替えます（[翻訳ガイドの AI プロバイダー設定](translate.md) 参照）。

---

## API キーが Git に入ってしまう（漏洩注意）

**症状:** `openai.apiKey` に実際のキーを直接書いて、`.mdait/mdait.json` をコミットしてしまった。

**原因:** `.mdait/.gitignore` は `logs/` のみを無視します。**`mdait.json` は Git 追跡対象**なので、キーを直書きすると漏洩します。

**対処:**

- 環境変数参照に切り替える: `"apiKey": "${env:OPENAI_API_KEY}"`。
- 既にコミット済みのキーは**無効化（ローテーション）**してください。履歴からの削除だけでは不十分です。
- `mdait: セットアップ診断` は直書きキーを検出して警告します。

---

## 原文の見出しを消したら訳文も消えた

**症状:** 原文のセクションを削除/改名して Sync したら、対応する訳文（手修正済みでも）が消えた。

**原因:** `sync.autoDelete`（既定 `true`）が、原文に対応の無い「孤立ユニット」を自動削除します。

**対処:**

- 手動 Sync では、翻訳済みの孤立ユニットを削除する前に**確認ダイアログ**が出ます（保存時の自動 Sync では出ません）。意図しない場合はキャンセルしてください。
- 消えても Git で復旧できます（`git diff` / `git checkout`）。
- 削除判断を常に手動にしたい場合は `"sync": { "autoDelete": false }` にします。`need:verify-deletion` が付き、確認後に手動削除できます。

---

## マーカーを手で消した／`sync.level` を途中で変えた

**症状:** 予期しない再翻訳や、Git の差分が大量に出る。

**原因:**

- マーカー（`<!-- mdait ... -->`）を手で削除・書き換えると、Sync が新規ユニットと誤認することがあります。
- `sync.level` を変えるとユニット境界がずれ、既存マーカーと食い違います。

**対処:**

- マーカーは手で編集しないでください。フラグのリセットは `mdait.sync` の再実行で行います。
- `sync.level` を変えたら、全ファイルを**再 Sync** してください（変更検知時に通知が出ます）。

---

## まず試すこと

1. `mdait: セットアップ診断（Diagnose Setup）` を実行する（設定・ディレクトリ・AI・キーを一括点検）。
2. それでも解決しなければ [getting-started](getting-started.md) のワークフローを最初から確認する。
3. 設定項目の詳細は [config-reference](config-reference.md) を参照する。
